# SKILL — photo-execute (Stage 5)

Version: 0.4 (monthly buckets renamed `YYYYMM00_`; D13 to-be-checked mod:
`--no-date` routes by each file's own date (Card 5); AI-images only if planned
`--ai-confirmed`)

Run ONE owner-approved plan: copy files to their planned destinations with
SHA-256 verification. **The only stage that writes to the drive.** Source
files are never moved, modified, or deleted (D2 copy-only) — the script has
no delete/move/rename call against any source path.

Runs on any text model. Requires: Python 3 (stdlib only), the shared
`scripts/` folder, plans generated by `photo-plan` and approved by the owner.

> Bucket names below are written with the ENGLISH defaults. They are not
> literals: every one resolves from the owner pack's language at run time.

## Inputs / outputs

| In | `plan/plan_PN-files.csv` + `plans.json` (on an indexed dump both written by `photo_index.py freeze`) + batches.json (status=approved) |
| Out | files copied onto the drive; `plan/execution-log_PN.md` + `execute-state_PN.json`; batches advance to `done` |

## Workflow

**1. Dry-run first — always** (dry-run is the script default):

    python3 scripts/photo_execute.py "<workdir>" --plan N

Verifies: every batch approved, every source file exists and is readable,
every destination inside the allowlist, free space ≥ plan size + 1 GB,
which folders need creating, destination same-name files. Writes nothing.

**2. Real copy** — only after the dry-run is clean:

    python3 scripts/photo_execute.py "<workdir>" --plan N --go

Per file: copy to `<name>.part` → SHA-256 both sides → rename into place.
Mismatch deletes the `.part` copy (never the source) and retries once, then
flags. Existing destination file: identical hash = already-present (verified);
different hash = flagged, both sides untouched — **never overwrite**.
`skip_dupe` rows are logged, never copied.

**3. Resume / verify**: re-running the same command skips rows already
verified in `execute-state_PN.json` — a run can stop mid-plan safely. When
every copy row of a batch is verified, the batch is advanced to `done` via
`photo_classify_set.py` automatically.

**4. No-date plan (D13 to-be-checked mod)** — after the batch plans, execute
the auto-routed no-date files (a no-date VIDEO → `YYYY00_To-be-checked` (its own modify year); a no-date STILL → one `_To-be-checked/<import>` folder that claims no year (Card 5); a manifest scanned before Card 5 still uses the dump's `YYYYMM00_To-be-checked`;
`YYYYMM00_AI-images` only when photo_plan ran with `--ai-confirmed`):

    python3 scripts/photo_execute.py "<workdir>" --no-date        # dry-run
    python3 scripts/photo_execute.py "<workdir>" --no-date --go

Same copy/verify machinery; no batch approval gate (no-date files belong to
no batch); destinations must still sit under dest_root. State/log:
`execute-state_no-date.json` / `execution-log_no-date.md`.
`photo_run.py finish` runs this automatically.

## Hard rules

- One plan per run — there is no execute-everything flag.
- Execution order = smallest plan first (trust ladder); after the FIRST real
  copy of a campaign, pause for the owner's Finder spot-check before
  continuing.
- Allowlist: destinations must sit under dest_root (D5) or a path the plan
  explicitly declares (`dest.path`, `overrides`) — the script aborts before
  any write otherwise.
- No-date files are in no batch plan CSV — they are executed only through
  the dedicated `--no-date` mode (D13 routing, gate 5 amended).
- The destination filename comes from the plan CSV, which since D13 carries
  the extension-corrected name for mislabeled files.
- Any flag in `execution-log_PN.md` = stop and show the owner; do not proceed
  to the next plan with unresolved flags.

## Exit criteria (per campaign)

- All execution logs show 0 flags; every copy checksum-verified.
- Spot-check ≥5 copied files per destination type render correctly.
- Recount destination folders vs plan totals; report the table to the owner.
